## 2. プロジェクト概要

**Pandora** は、自分自身を実験台にして「日常の迷信や噂の効果」を検証する個人実験 × 共同探究型 Web プラットフォームである。AI が題材ごとに最適な実験設計（チェック項目）を自動生成し、ユーザーは日々記録するだけで素人でも"ちゃんとした実験"ができる体験を提供する。

ハッカソン提出を想定した **MVP**（実ユーザーに触ってもらえる最小限の動作レベル）を、Web（PC/スマホブラウザ対応）として **約 1 週間** で実装する。

詳細なコンセプトは `/idea.md` を参照。

## 3. 機能要件 (Functional Requirements)

### FR-1: ユーザー認証
- **FR-1.1**: ユーザーは新規登録・ログイン・ログアウトができる。
- **FR-1.2**: 認証方式は **AWS Cognito** によるメール+パスワード（最速で実装でき、AWS スタックと整合）。
- **FR-1.3**: 未認証ユーザーは公開された題材・結果を閲覧できる（読み取り専用）。

### FR-2: マイ研究所（機能①）
- **FR-2.1**: ユーザーは研究題材（自由テキスト）を投稿できる。
- **FR-2.2**: AI（AWS Bedrock 経由の LLM）が題材を解析し、以下を生成する:
  - 確からしさの提示（Web/論文検索ベースの要約）
  - 個人レベルでの実験手順
  - 実施方法の候補（複数案）
  - 推奨スケジュール（頻度・時間）
  - 効果測定の方法
  - 日次チェック項目（数値入力 / セレクト / チェックボックス / スライダー / 画像アップロード / テキスト の組み合わせ）
- **FR-2.3**: ユーザーは AI 生成の実験設計を確定（必要に応じて簡易編集）して「自分の研究」として開始する。
- **FR-2.4**: ユーザーは日次でチェック項目を記録できる。
- **FR-2.5**: 過去の記録を時系列・グラフで閲覧できる。

### FR-3: 題材・結果の公開（機能②）
- **FR-3.1**: 全データはデフォルト公開（個人情報を含まない前提運用）。Q8 回答に基づく。
- **FR-3.2**: 公開された研究題材・結果は誰でも閲覧できる。
- **FR-3.3**: 一覧画面で題材・実施者・経過日数・結果サマリを表示する。
- **FR-3.4**: 題材詳細画面で日次記録（グラフ・画像含む）が見える。

### FR-4: 題材グループ（機能③）
- **FR-4.1**: 同じ題材に取り組むユーザーは自動的に「題材グループ」に属する（題材ID単位）。
- **FR-4.2**: グループページで全メンバーの記録を一覧・比較できる（読み取り専用）。
- **FR-4.3**: グループ内で各記録に対し**コメント**を投稿できる。
- **FR-4.4**: グループ内で各記録に対し**リアクション**（絵文字スタンプ等）を付与できる。

### FR-5: 画像アップロード
- **FR-5.1**: ユーザーは日次チェック時に画像をアップロードできる。
- **FR-5.2**: 画像は **AWS S3** に保存し、CloudFront 経由（または S3 署名付きURL）で配信する。

### FR-6: AI 連携
- **FR-6.1**: AI 機能はすべて **AWS Bedrock** 上のモデルを利用する（Claude on Bedrock を第一候補）。
- **FR-6.2**: 題材解析・実験設計生成は同期 API として実装する（必要時にストリーミング対応も検討）。

## 4. 非機能要件 (Non-Functional Requirements)

### NFR-1: パフォーマンス
- **NFR-1.1**: 想定同時ユーザー数は **数人〜十数人**（審査員 + チーム）。スケール要件は最小。
- **NFR-1.2**: 通常画面の初期表示は 3 秒以内を目標。
- **NFR-1.3**: AI 生成（題材解析〜実験設計）は **30 秒以内** を目標。

### NFR-2: ユーザビリティ
- **NFR-2.1**: PC ブラウザ + スマホブラウザの両方でレスポンシブに動作する。
- **NFR-2.2**: 日本語UIをデフォルトとする。
- **NFR-2.3**: 「沼る」体験を演出するため、UI 設計は次の観点を重視:
  - 他者の研究結果が見たくなる導線（ホーム = タイムライン）
  - 記録のリズムを生む通知/ストリーク表示（実装は MVP 範囲で簡易に）
  - 比較が一目で分かるグループ画面

### NFR-3: セキュリティ
- **NFR-3.1**: Security Baseline 拡張は **無効化** （Q: B 回答 / プロトタイプ運用前提）。
- **NFR-3.2**: ただし最低限以下は遵守:
  - 認証情報・APIキーをコードにハードコードしない（環境変数 / AWS SSM / Secrets Manager）
  - HTTPS 通信
  - Cognito によるセッション管理

### NFR-4: 信頼性・運用
- **NFR-4.1**: ハッカソン審査期間中（数日）は安定稼働すること。
- **NFR-4.2**: 障害発生時はデモ用の代替手段（録画動画等）を用意する想定（運用ポリシー）。

### NFR-5: テスト
- **NFR-5.1**: Property-Based Testing 拡張は **無効化** （Q: C 回答 / シンプルCRUD想定）。
- **NFR-5.2**: 主要ユースケースに対するハッピーパスの軽量な単体・統合テストを実施する。

### NFR-6: 保守性
- **NFR-6.1**: TypeScript の strict モードを有効化。
- **NFR-6.2**: 主要ロジックには JSDoc 等で意図を残す（過剰なコメントはしない）。

## 5. 技術スタック（暫定確定）

| レイヤー | 技術 | 備考 |
|----------|------|------|
| フロントエンド | **Next.js 14+ / TypeScript / React** | App Router |
| UI / スタイリング | Tailwind CSS + shadcn/ui (推奨) | MVP速度重視 |
| ホスティング (FE) | **Vercel** | Next.js 標準 |
| API レイヤー | **Next.js Route Handlers** (`app/api/*` / TypeScript) | Vercel 上で動作。AWS API Gateway / Lambda は使用しない |
| 認証 | **AWS Cognito** | User Pool + Hosted UI もしくは Amplify Auth |
| データベース | **Amazon DynamoDB** | NoSQL / シングルテーブル設計を想定 |
| ストレージ | **Amazon S3** + CloudFront | 画像配信 |
| AI / LLM | **AWS Bedrock** (Claude モデル想定) | 題材解析・実験設計生成・Web要約 |
| Web/論文検索 | 外部 API (Tavily / Brave / 後段で確定) | Bedrock からツール呼び出し |
| IaC | **AWS CDK** (TypeScript) | 推奨 |
| CI/CD | GitHub Actions | Lint/Build/Deploy |

> 注: 上記は要件分析時点での **推奨構成**。最終確定はワークフロー計画/アプリケーション設計の段階で再検証する。

## 6. ユーザー・公開範囲・データ

- ユーザー単位 = Cognito User
- すべての投稿・記録は公開前提（個人情報を含めない運用）
- 削除・非公開機能は **MVP スコープ外**（明示的に外す）

---

## 7. スコープ外（MVP では作らないもの）

- ネイティブモバイルアプリ
- リアルタイムチャット、プッシュ通知
- 公開/非公開の細粒度制御
- 多言語対応（日本語のみ）
- 課金・広告
- 管理者機能（モデレーション）
- メールリンク認証、SSO（Google/Apple 等）

## 10. 主要な前提と未決事項

**前提（要件確定）**:
- ハッカソン MVP / 約1週間 / 全3機能 / Web のみ / Next.js + AWS / Bedrock / 全データ公開

**未決事項（後続フェーズで確定）**:
- DynamoDB のテーブル設計（シングルテーブル vs マルチテーブル）
- Bedrock で利用する具体的モデル（Claude 4.x の選定）
- Web/論文検索の外部API選定（Tavily / Brave / Bing Search）
- 認証は Cognito Hosted UI vs Amplify Auth UI
- Vercel ↔ AWS 間の認証連携方法（Cognito JWT を Next.js Route Handler 内でVerify）
- Vercel から AWS（DynamoDB / S3 / Bedrock）への認証方式（IAM ユーザーのアクセスキー vs OIDC 連携 (Vercel ↔ AWS STS AssumeRole)）

## 11. 主要要件サマリ

- **Web MVP** を約1週間で構築
- **3機能を全て** 実装（マイ研究所 / 公開 / グループ）
- **Next.js (Vercel) + AWS マネージドサービス** 構成（API は Next.js Route Handlers に集約。API Gateway / Lambda は使わない）
- **AWS Bedrock** で AI 実験設計を生成
- 公開前提・小規模ユーザー想定・拡張ルールはOFF
