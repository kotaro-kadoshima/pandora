# Unit of Work — Story Map

ストーリーをユニットへ割り当てる。U1（Web App）が UI/API/ロジックを実装し、U2（AWS Infra）が必要なリソースを提供する責務分担。

---

## 1. ストーリー × ユニット マッピング

| Story | エピック | 主担当 | U2 必要リソース |
|-------|---------|:------:|---------------|
| US-01 新規登録 | E1 認証 | **U1** | Cognito User Pool / App Client |
| US-02 ログイン / ログアウト | E1 認証 | **U1** | Cognito |
| US-03 題材投稿 + AI 実験設計の生成 | E2 マイ研究所 | **U1** | DynamoDB / Bedrock / IAM |
| US-04 AI 提案を確認して研究を開始 | E2 マイ研究所 | **U1** | DynamoDB |
| US-05 日次でチェック項目を記録 | E3 日次記録 | **U1** | DynamoDB |
| US-06 自分の経過を時系列・グラフで閲覧 | E3 日次記録 | **U1** | DynamoDB |
| US-07 記録時の画像アップロード | E3 日次記録 | **U1** | S3 / IAM（PutObject） |
| US-08 ゲストでも公開タイムラインを閲覧 | E4 公開 | **U1** | DynamoDB |
| US-09 題材詳細で日次記録を閲覧 | E4 公開 | **U1** | DynamoDB / S3（GET） |
| US-10 同題材グループの記録を一覧比較 | E5 グループ | **U1** | DynamoDB |
| US-11 他者の記録にコメント | E5 グループ | **U1** | DynamoDB |
| US-12 他者の記録にリアクション | E5 グループ | **U1** | DynamoDB |
| US-13 AI が題材の確からしさを根拠付きで提示 | E6 AI | **U1** | Bedrock / 外部検索API（後段で確定） |

すべての Must / Should ストーリーが U1 担当。U2 は **基盤整備** として横断的にサポート。

---

## 3. U2 が用意すべきリソース（ストーリー駆動の最小集合）

| ストーリー群 | 必要リソース |
|------------|------------|
| 認証系 (US-01,02,11,12 等) | Cognito User Pool / App Client / JWKS |
| 研究・記録系 (US-03〜10) | DynamoDB シングルテーブル + GSI |
| 画像 (US-07, US-09) | S3 バケット + CORS / 署名付きURL用 IAM |
| AI (US-03, US-13) | Bedrock モデル呼び出し権限 |
| 横断 | IAM ロール / VercelからのAWSアクセス手段（OIDC or IAM ユーザー）|

---

## 4. クリティカルパス（実装順）

1. **U2**: Cognito + DynamoDB + S3 + Bedrock 権限の最小構成
2. **U1**: 認証 middleware → 公開タイムライン閲覧（US-08, US-09）
3. **U1**: 題材投稿 + AI 生成（US-03）
4. **U1**: 設計確定 + 日次記録 + 画像（US-04, US-05, US-07）
5. **U1**: 経過閲覧（US-06）
6. **U1**: グループ機能（US-10, US-11, US-12）
7. **U1**: 確からしさ強化（US-13、Should 優先度）
